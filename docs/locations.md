# Доступность локаций

В таблице `locations` два независимых параметра:

| Поле БД | Поле API | Значение |
| --- | --- | --- |
| `is_open` | `isOpen` | `true` — контент открыт; `false` — локация в разработке |
| `min_level` | `minLevel` | Минимальный уровень персонажа, целое число от 1 |

Новые локации по умолчанию закрыты и требуют уровень 1. Миграция `0025_location_access`
открывает существующие Площадь (`square`), Рынок (`rialto`) и Сити парк (`market`).
Парк Победы (`park`), Солдатский лес (`forest`), Липяги (`railway`) и другие локации
остаются в разработке. Сид применяет такие же значения при создании новой базы.
Пороги пока равны 1: будущие уровни открытия задаются отдельно при подготовке контента.

## Проверки

1. Сервер разрешает обход игрокам из `ADMIN_IDS` (ID Telegram, как в существующей админке)
   и всем игрокам на dev-стенде с `DEV_BYPASS_AUTH=true`.
2. Для остальных `isOpen=false` запрещает вход независимо от уровня.
3. В открытую локацию можно войти при `player.level >= minLevel`.

Используется существующий серверный признак dev-стенда. `NODE_ENV`, `VITE_DEV_MODE`,
`VITE_ADMIN_PANEL` и параметры запроса не дают права на обход ограничений.
На обычном стенде `DEV_BYPASS_AUTH=false`; список админов настраивается сервером.

Общая функция `getLocationAccess` задаёт одинаковый порядок проверок на сервере и
карте. Сервер повторно проверяет данные из БД при входе, чтении состояния,
действии в локации и начале боя. Запрещённый вход возвращает `403` с кодом
`LOCATION_IN_DEVELOPMENT` или `LOCATION_LEVEL_REQUIRED` до изменения положения,
сокет-комнат и квестов.

## Карта

Все точки видны и открывают карточку с изображением и описанием.

| Состояние | Отметка на карте | Карточка и переход |
| --- | --- | --- |
| Открыта, уровень достаточен | Обычная точка, «Доступна» или «С N уровня» | Активная кнопка «Перейти» |
| В разработке | Серая точка с замком, «Скоро появится» | Пояснение о разработке, неактивная кнопка |
| Открыта, уровень недостаточен | Жёлтая точка с замком, «С N уровня» | Требуемый и текущий уровни, неактивная кнопка |
| Админ / dev | Статус разработки остаётся видимым | Пояснение о доступе для тестирования, активная кнопка |

Для закрытой локации с порогом выше 1 карточка уточняет: «После открытия — с N уровня».
При повышении уровня карта обновляет данные и пересчитывает доступность.
Если правила изменились после загрузки карты, сервер отклонит запрещённый переход;
карточка покажет ошибку и обновит список локаций.

## Настройка и обновление

Сервер автоматически применяет миграцию при запуске. Она добавляет колонки без
пересоздания таблицы и сохраняет связанных игроков, мобов, события и задания.
Сид не перезаписывает `is_open` и `min_level` существующих строк при перезапуске.

Пример открытия Парка Победы с 5 уровня в будущей миграции:

```sql
UPDATE locations SET is_open = 1, min_level = 5 WHERE id = 'park';
```

Чтобы закрыть локацию, достаточно установить `is_open = 0`; требуемый уровень
при этом сохраняется. Изменения правил следует выкатывать миграцией с перезапуском
сервера: при старте у обычных игроков в недоступных локациях сбрасывается
`currentLocationId`, а незавершённый бой с мобом завершается как побег без награды.
На главном экране им предлагается выбрать точку на карте. На админов и dev это
перемещение не распространяется.

Проверки: `npm run typecheck`, `npm run test --workspace @mmobot/server`, `npm run build`.
Тесты локаций используют временную БД и заглушки уведомлений и сокетов.
