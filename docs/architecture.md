# Архитектура и навигация по проекту

Проект — npm-монорепозиторий с клиентом, сервером и общими контрактами. Внутри приложений код сгруппирован по игровым областям. Это модульный монолит: сервер запускается одним процессом, использует одну SQLite-базу и существующие транзакции.

## Верхний уровень

| Путь | Ответственность |
| --- | --- |
| `apps/client/` | React Mini App, маршруты экранов, HTTP-запросы и Socket.IO-клиент. |
| `apps/server/` | Express API, игровая логика, Socket.IO-сервер и Telegram-бот. |
| `packages/shared/` | Общие DTO, типы событий, определения боя, оружия и пассивок. |
| `docs/` | Эта карта, правила локаций и описание боевой системы. |
| `API.md` | Описание API. Фактические обработчики находятся в серверных модулях. |
| `package.json`, `package-lock.json` | Workspaces, общие команды и зафиксированные зависимости. |
| `tsconfig.base.json` | Общие настройки TypeScript. |
| `Dockerfile`, `railway.json` | Сборка и запуск приложения в контейнере. |


## Клиент

```text
apps/client/src/
  main.tsx                 # React DOM и внешние провайдеры
  app/
    App.tsx                # сессия, состояние приложения, подписки и маршруты
    layout/MainLayout.tsx  # общий каркас экранов и навигация
    modals/                # сборка модальных окон разных игровых областей
    ui/Loading.tsx         # загрузка приложения
    styles.css             # глобальные стили
  features/
    <область>/
      api.ts               # HTTP-запросы этой области, если они есть
      components/          # экраны и специализированные компоненты
      hooks/               # специализированные хуки, если нужны
      lib/                 # вспомогательные функции этой области
  shared/
    api/http.ts            # единый Axios, обработка ошибок, Bearer-заголовок
    api/socket.ts          # создание Socket.IO-подключения
    hooks/                 # общие хуки
    lib/                   # Telegram WebApp и предзагрузка изображений
    ui/                    # общие анимации, оболочки окон и спиннер
```

| Область в `features/` | Где искать функциональность |
| --- | --- |
| `auth` | Запрос входа через Telegram. |
| `character` | Создание персонажа, профиль, очки характеристик, изображения персонажей. |
| `players` | Онлайн-игроки и восстановление последнего действия. Пока только API-функции. |
| `locations` | Главный экран `Home`, карта `GameMap`, `ActionCards`, карточки действий в `components/actions/`, загрузка текущей локации и её фонов. |
| `combat` | `Fight` для PvP, `PveFight` для PvE, общий `BattleScreen`, `MovePanel`, `BattleConsole`, эффекты урона, окна боя и `useBattlePlayback`. |
| `inventory` | Инвентарь, окно предмета `ItemModal`, экипировка и использование предметов. |
| `items` | Каталог и общие сведения о предмете в `ItemDetails`. |
| `mobs` | API управления мобами; административный интерфейс находится в `admin`. |
| `shop` | Экран магазина, покупка и продажа. |
| `trades` | Экран обмена, выбор партнёра и предметов, уведомления об обмене. |
| `friends` | Экран команды/друзей `Team`, заявки и поиск. |
| `quests` | Экран заданий `Tasks`, получение награды, анимация выдачи. |
| `casino` | Игры `MinesGame`, `BlackjackGame`, `LadderGame`, общая рамка и игральная карта. |
| `leaderboard` | Таблица лидеров. |
| `notifications` | Список уведомлений и кнопка открытия. Конкретные приглашения лежат в `combat` и `trades`. |
| `admin` | Входной экран `Admin.tsx` и панели управления игроками, мобами, предметами и заданиями. |

Общие компоненты в `shared/ui` не импортируют игровые экраны. Идентификаторы окон находятся в `shared/ui/modal/types.ts`; выбор окна по идентификатору — в `app/modals/Modal.tsx`. Если экрану нужно конкретное окно своей области, он импортирует его напрямую.

`public/mapMat.png` — карта, доступная по `/mapMat.png`. Изображения локаций и персонажей получает клиент с сервера по прежним URL. `index.html` остаётся HTML-точкой входа Vite, `vite.config.ts` — настройкой сборки и dev-сервера.

## Сервер

```text
apps/server/src/
  index.ts                 # запуск HTTP, Socket.IO и фоновых задач
  bot.ts                   # отдельная точка входа Telegram-бота
  app.ts                   # создание Express и порядок подключения маршрутов
  config/env.ts            # чтение корневого .env и переменных окружения
  database/
    connection.ts          # единственное подключение SQLite/Drizzle
    schema.ts              # таблицы и Row-типы
    initialize.ts          # миграции, совместимость схемы и сидирование
    mappers.ts             # преобразование строк БД в DTO
    index.ts               # публичный вход для подключения и инициализации
  modules/                 # игровые области и их HTTP-обработчики
  infrastructure/
    realtime/socket-server.ts  # комнаты, подключения и отправка событий
    telegram/notifications.ts  # очередь уведомлений Telegram
  http/serve-client.ts     # раздача собранного клиента и SPA fallback
  jobs/maintenance.ts      # периодическая очистка событий и зависших сессий
  shared/time.ts           # существующие правила игрового времени UTC+4
```

| Модуль в `modules/` | Файлы и ответственность |
| --- | --- |
| `auth` | `auth.ts`: Telegram initData, JWT и middleware; `routes.ts`: вход и создание записи игрока с уникальным friendId. |
| `admin` | `players.routes.ts`: поиск и редактирование игроков. Управление предметами, мобами и заданиями находится в соответствующих модулях. |
| `players` | `routes.ts`: профиль, характеристики, конструктор и каталог внешности; `online.routes.ts`: список онлайн; `level.ts`: опыт и уровни; `regen.ts`: регенерация; `last-action.ts`: восстановление игровой активности. |
| `locations` | `routes.ts`: список, вход и действия; `access.ts`: ограничения доступа; `state.ts`: сборка состояния; `presence.ts`: игроки в памяти; `daily-activities.ts`: ежедневные активности. |
| `combat` | `routes.ts`: PvE HTTP; `pve.ts`: состояние, ходы, награды и респаун; `pvp.ts`: дуэли и их маршруты; `loot.ts`: разбор и розыгрыш добычи. |
| `combat/battle` | `engine.ts`: расчёт раунда; `state.ts`: версии, повторы команд и публичное состояние; `stats.ts`: снимки бойцов; `potions.ts`: подготовка и списание зелий. |
| `inventory` | `routes.ts`: экипировка и использование; `store.ts`: выдача, поиск экземпляров, ограничения во время боя. |
| `items` | `routes.ts`: CRUD и валидация; `catalogs/weapons.ts` и `catalogs/meme-items.ts`: стартовые каталоги. |
| `mobs` | `routes.ts`: CRUD мобов и проверка таблиц добычи. |
| `shop` | `routes.ts`: магазин, покупка и продажа с транзакциями. |
| `trades` | `routes.ts`: приглашения, предложения, готовность и атомарный обмен. |
| `friends` | `routes.ts`: поиск и заявки; `overview.ts`: DTO друга и сборка списка друзей/заявок. |
| `quests` | `routes.ts`: каталог заданий, ежедневное назначение, прогресс, награды и HTTP-обработчики. |
| `casino` | `routes.ts`: сессии, ставки и расчёт результатов трёх игр. |
| `leaderboard` | `routes.ts`: рейтинг по очкам. |

`routes.ts` обозначает модуль, предоставляющий HTTP-обработчики. Некоторые существующие модули также содержат их прикладную логику: торговля, задания, казино и PvP. По мере роста конкретного модуля можно выделять его сервисы и запросы к БД; создавать пустые слои для каждого небольшого файла не требуется.

Подключение БД отделено от DTO и инициализации, поэтому модуль, которому нужен только `db`, импортирует `database/connection.ts`. Это уменьшает ненужные зависимости. Существующие взаимодействия между игровыми системами, включая отправку socket-событий, сохранены; строгая изоляция доменов и внедрение зависимостей потребовали бы отдельного рефакторинга логики.

### Данные, миграции и пути

- `apps/server/drizzle/` и `drizzle/meta/` — последовательность SQL-миграций, снимки схемы и журнал Drizzle. Порядок и содержимое сохранены.
- `drizzle.config.ts` указывает на `src/database/schema.ts`.
- `apps/server/data/characters/` и `data/location/` — исходные SVG. Они продолжают раздаваться по `/character-images/` и `/location-images/`.
- SQLite-файл определяется `DATABASE_PATH`. Существующее разрешение относительного пути от рабочего каталога сохранено. Для развёртывания предпочтителен абсолютный путь к постоянному тому.
- `dist/`, `node_modules/`, `*.tsbuildinfo` и SQLite-файлы — результаты сборки, установленные зависимости и локальное состояние; исходный код там не редактируют.

## Общий пакет

`packages/shared/src/index.ts` — публичная точка входа `@mmobot/shared`. Импорты клиентов пакета сохраняются: `import { ... } from "@mmobot/shared"`.

- `contracts/` — DTO по областям: `auth`, `players`, `mobs`, `items`, `locations`, `combat-api`, `trades`, `friends`, `quests`, `casino`, `leaderboard`, `activity`, `realtime`.
- `combat.ts` — модель раундового боя, действий и событий.
- `weapons.ts` — свойства оружия, редкости, определения пассивок и их параметры.

Контракты не импортируют код приложений, React, Express или доступ к БД. Связи между DTO оформляются через `import type`.

## Как добавлять изменения

1. Найти игровую область в таблицах выше. Новый экран или обработчик добавлять в существующую область; новый домен — в отдельную папку `features/` и/или `modules/`.
2. Общий формат запроса, ответа или события описать в `packages/shared/src/contracts/` и экспортировать через `index.ts`.
3. На сервере добавить обработчик в соответствующий модуль. Новые наборы маршрутов подключать в `app.ts`, сохраняя middleware авторизации и порядок регистрации.
4. На клиенте добавить запрос в `features/<область>/api.ts`, экран — в `components/`, маршрут — в `app/App.tsx`.
5. Общий UI переносить в `shared` только если он не зависит от игровой области. Специализированный хук или окно держать рядом с его потребителем.
6. При изменении схемы БД создавать миграцию через Drizzle. При изменении игровой логики дополнять соответствующие серверные тесты.

Не создавать папки `utils`, `helpers` или `components` в корне приложения для несвязанных функций. Использовать прямые импорты конкретных файлов внутри приложения; общий публичный вход сохраняется у пакета `@mmobot/shared`.

## Проверки

Из корня репозитория:

```sh
npm run typecheck
npm run build:prod
npm test --workspace @mmobot/server
```

Серверные тесты лежат в `apps/server/tests/`, используют временные базы и подменяют Telegram-уведомления. Они проверяют бои, PvP, миграции, доступность локаций, добычу, предметы, обмен, задания и казино.

При реорганизации до изменений обнаружено одно существующее падение: `quests.test.mjs`, проверка запрета создания задания обычным игроком. В `modules/auth/auth.ts` проверка внутри `requireAdmin` закомментирована, поэтому возвращается `200` вместо ожидаемого `400`. Поведение оставлено прежним в рамках сохранения логики; для включения ограничений нужен отдельный согласованный фикс. До и после переноса результат одинаков: 82 из 83 тестов проходят.

Дополнительно проверена сборка с удалением старых артефактов из рабочих каталогов и HTTP-запуск с временной БД: `/health`, главная страница, SPA-маршрут `/Profile`, JS/CSS, оба каталога изображений, авторизация, профиль, каталог внешности и список локаций работают.

При HTTP-проверке также подтверждён существующий конфликт API и SPA: прямой запрос `/Inventory` попадает в middleware `/inventory` из-за регистронезависимого сопоставления Express и без Bearer-токена возвращает `401`. Перенос сохраняет порядок и содержимое регистрации маршрутов, поэтому это поведение не изменено. Исправление пространства URL следует делать отдельной задачей.
