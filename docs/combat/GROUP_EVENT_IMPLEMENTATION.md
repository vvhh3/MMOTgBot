# Особая прогулка с компанией

Реализованы сбор группы через боковые «+» на Площади, временный вход в событие и командный раундовый бой. Первоначальные обсуждения: [игровой план](SPECIAL_GROUP_EVENT_PLAN.md), [план файлов и БД](SPECIAL_GROUP_EVENT_FILES_AND_DB.md).

**Как включить событие**

После запуска сервера автоматически применяется миграция `0036_group_events`. Она добавляет пять таблиц и не завершает существующие обычные бои. Сид добавляет карточку `special_walk` на Площадь после создания `locations.actions`.

Откройте админку → «События», задайте начало и конец, включите набор и сохраните. Время формы отображается в часовом поясе устройства; API использует настоящие UTC ISO-метки. Преобразование в принятую в проекте шкалу БД UTC+4 выполняет сервер. По умолчанию окна события нет: карточка недоступна, боковые «+» скрыты. Административные маршруты используют существующие `requireAuth` и `requireAdmin`.

Настраиваются минимальный уровень, противники каждой волны из каталога Площади, множители HP и атаки, таймер, общая длительность, опыт/монеты/очки и таблица добычи. В обычной волне ровно три моба, в последней — один босс. Можно добавлять и убирать промежуточные волны. Пустая таблица добычи использует лут выбранного босса, отфильтрованный по уровню группы при старте.

Стартовые настройки:

- Три обычные волны и финальный «Ильич вне расписания».
- Обычные мобы: HP ×1, атака ×0,75; босс: HP ×2,5, атака ×1,25.
- 60 секунд на раунд, 45 минут на прохождение; окно входа задаётся отдельно.
- Награда каждому не вышедшему участнику: 150 опыта, 100 монет, 50 очков и независимый розыгрыш добычи.

**Сбор группы и одиночные действия**

Во время открытого события на Площади свободные боковые места показывают «+». Нажатие открывает своих подтверждённых друзей. Первое успешное приглашение одной транзакцией создаёт группу; закрытие окна выбора ничего не создаёт. Выбранная позиция резервируется на две минуты. При принятии появляются персонаж, имя и HP друга. Основной персонаж у каждого участника остаётся в центре.

Создатель — лидер. Каждый подтверждённый участник может пригласить своего друга на свободное место; лидер запускает событие и может исключать участников. Для старта нужны ровно три готовых игрока, которые находятся на Площади, в сети, живы, завершили обучение и свободны от других занятий. Лобби живёт десять минут. Изменение состава или сборки сбрасывает готовность. Выход лидера распускает лобби.

При обычной прогулке, создании PvP и принятии входящего PvP игра предлагает выйти из группы. Отмена ничего не запускает. Подтверждение сначала ожидает успешного серверного выхода, затем продолжает действие. Сервер независимо возвращает `409/PARTY_EXIT_REQUIRED`, поэтому прямой запрос или другая вкладка не обходят правило. Противник, уже состоящий в группе, недоступен для запуска дуэли. Старое приглашение на обмен тоже не может перезаписать групповое занятие.

**Командный бой**

Каждый живой игрок выбирает одного из живых противников и приём. Защита и зелье применяются к своему персонажу; побочные враждебные эффекты используют выбранного противника. Состав и характеристики фиксируются при старте. Уровень противников определяется максимальным уровнем группы. Правки административной конфигурации не меняют начатый бой.

ИИ фиксирует приём и цель до заявок игроков. Раунд разрешается после выбора всех живых участников либо по дедлайну. Защита и лечение сохраняют текущие приоритеты, равные приоритеты перемешиваются. Если выбранная цель погибла раньше действия, атака перенаправляется на первого живого противника. Пропущенный ход остаётся ожиданием, без бесплатной атаки или защиты.

Урон, блок, отражение, криты, пассивки, зелья и эффекты используют общий расчёт из `modules/combat/battle/action.ts`. `engine.ts` сохраняет обёртки и формат обычных PvE/PvP. Групповой раунд находится в `group-round.ts`; периодические эффекты выполняются один раз на общий раунд, включая границу между волнами. Метки долга разных источников сохраняют владельцев.

HP, кулдауны и временные эффекты продолжаются между волнами. Допустимо одно зелье на игрока за прохождение; оно списывается только при исполнении. Погибшие наблюдают и не задерживают раунд. Команда может закончить событие оставшимися игроками; погибшие получают победную награду вместе с командой. Явный выход из начатого прохождения исключает из дальнейших волн и наград, сохраняет текущий HP и освобождает занятость.

Отключение приложения выходом не считается. При возвращении восстанавливаются HP, волна и уже принятый ход. Обычная регенерация и смена сборки во время боя закрыты. Два полностью пропущенных командой раунда или общий срок завершают прохождение без награды. Закрытие окна набора прекращает новые приглашения/старты и закрывает лобби, но позволяет закончить начатые прохождения.

Награды, квитанции и завершение записываются одной транзакцией. Уникальность `(run_id, player_id)` и сохранённые `requestId` предотвращают повторную выдачу. Награда не зависит от последнего удара. Отдельный лимит числа побед за окно в этой версии не включён; повторный сбор группы возможен, пока открыт вход.

**Файлы и данные**

- Сервер: `apps/server/src/modules/group-events/`; настройка — `modules/admin/group-events.routes.ts`.
- Клиент: `apps/client/src/features/group-events/`; карточка — `features/locations/components/actions/SpecialWalkCard.tsx`; настройка — `features/admin/components/GroupEventAdmin.tsx`.
- Контракты: `packages/shared/src/contracts/group-events.ts`; общий контекст нескольких бойцов — `battle-core.ts`.
- Таблицы: `group_event_windows`, `event_parties`, `event_party_members`, `group_event_runs`, `group_event_rewards`.
- Новых колонок игрока нет: `LastAction` получает `GroupEventLobby` и `GroupEvent`. Членство определяется таблицей участников, независимо от сокетов и текущей локации.
- Миграция сгенерирована как custom-миграция Drizzle из DDL схемы. Снимок `0036_snapshot.json` согласован со схемой, включая уже существующую миграцию `0035_session_retention`; `drizzle-kit check` проходит.

Основные маршруты: `GET /group-events/me`, `POST /group-events/:id/parties`, `POST /event-parties/:id/{invite,respond,ready,remove,leave,start}`, `GET /group-event-runs/:id`, `POST /group-event-runs/:id/{actions,leave}`. Любые изменения групп передаются персональным событием `groupEventUpdate`, содержащим публичный обзор. Скрытые команды и счётчики повторов наружу не выдаются. Публичная ревизия позволяет игнорировать запоздавшие ответы.

**Проверки и баланс**

Команды из корня:

```sh
npm run typecheck
npm test --workspace @mmobot/server
npm test --workspace @mmobot/client
npm run build:prod
node docs/combat/simulate-group-event.mjs
```

Новые проверки покрывают приглашения и вместимость, готовность, ограничения прогулки/PvP/обмена, три независимых выбора из одного снимка, общие эффекты, разные группы, тайм-аут, восстановление в новом процессе, атомарный откат наград и повтор команды, миграцию существующей БД и отображение боковых мест/шести бойцов.

Симуляция использует настоящий боевой расчёт, три одинаковых персонажа с экипировкой соответствующего уровня и одним зельем, без пассивок. Результаты сохранены в [group-event-balance-results.json](group-event-balance-results.json). В 100 испытаниях на каждый вариант уровни 1–8 с концентрацией атак дают 79–100% побед и около 19–24 раундов. Это ориентир для стартовых коэффициентов, а не оценка всех смешанных составов и пользовательских сборок. Числа доступны для дальнейшей настройки в админке.
