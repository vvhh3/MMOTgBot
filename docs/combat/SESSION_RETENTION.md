# Очистка завершённых боёв и событий

`jobs/maintenance.ts` удаляет завершённые `combat_sessions` и `pvp_sessions` через 24 часа после `last_action_at`. Вместе с сессией удаляются её JSON-журнал и `processedRequests`. У старых завершённых PvP-приглашений без `last_action_at` используется `creadet_at`.

Мгновенное удаление нарушило бы получение результата через HTTP после потери сокет-сообщения и успешный повтор последней команды. В течение суток результат и подтверждения команд доступны; после удаления запрос к старому ID возвращает 404. ID сессий используют `AUTOINCREMENT`, поэтому старый запрос не попадёт в новый бой.

Удаляются только PvE со статусами `victory`, `defeat`, `fled`, `aborted` и PvP со статусом `finished`. Возраст активного боя или приглашения сам по себе не делает его кандидатом на удаление. Проверка бездействия каждые 10 секунд сначала завершает заброшенные бои по существующим правилам и фиксирует время завершения. Новый результат хранится ещё сутки.

Удаление и очистка совпадающих ссылок `players.id_the_last_action` выполняются в одной транзакции. Проверяются участник, тип действия и ID сессии; другое занятие игрока сохраняется. Награды, HP, инвентарь, квесты и обучающий прогресс хранятся отдельно и при удалении сессий не пересчитываются.

Таблица `events` — отдельная история локаций, без привязки к ID боя. Она также хранит события прогулки для двухсекундного ограничения частоты действий. Существующий срок хранения в 7 дней сохранён: свежие события не удаляются при завершении боя. Квестовый прогресс записывается отдельно от журнала.

Очистка запускается при старте сервера и раз в минуту, до 500 строк из каждой таблицы за проход. При большом накоплении старые записи удаляются постепенно. Миграция `0035_session_retention.sql` добавляет только индексы для обслуживания; данные не удаляет. Она применяется обычным механизмом миграций при следующем запуске сервера.

Проверки в `maintenance.test.mjs` покрывают сроки хранения, активные и старые сессии, оба участника PvP, повторы финальных команд, сохранность наград/инвентаря/квестов, откат при ошибке, очистку ссылок, размер порций и таймеры обслуживания. `retention-migration.test.mjs` проверяет обновление существующей БД, сохранность записей, повторный запуск миграций, использование индексов, целостность и внешние ключи. Все проверки используют временные базы.
