# Социальные группировки

Реализовано 25 октября 2026 года. Группировки заменяют расы. Боевых бонусов от выбора нет.

## Поведение

- Новый персонаж выбирает группировку вместе с именем и аватаром. Без выбора сохранение недоступно.
- Доступны Нефоры (`nefors`), Нормисы (`normies`), Офники (`offniks`), Скуфы (`skufs`), Геймеры (`gamers`) и Анимешники (`anime`). Каталог, названия, цвета и описания общие для клиента и сервера: [factions.ts](../packages/shared/src/factions.ts).
- Группировка выбирается только при создании персонажа. Существующие персонажи сразу входят в игру: выбранная ранее группировка сохраняется, а персонажи без неё остаются без группировки. Их прогресс сохраняется.
- После создания выбор и смена группировки недоступны. Отдельный экран и API выбора удалены; повторное создание сервер отклоняет.
- В профиле под именем отображаются эмблема и название. Нажатие открывает вкладку группировок в рейтинге.
- В рейтинге есть вкладки «Игроки» и «Группировки». Для группировок доступны численность и суммарные текущие очки участников. Собственная группировка выделяется; есть кнопка обновления.
- Считаются только созданные персонажи с известной группировкой. Пустые группировки отображаются с нулевыми показателями. Незавершённые и ещё не выбравшие группировку персонажи не увеличивают её счётчики.
- Одинаковые значения выбранного показателя получают одинаковое место; дополнительные показатели и стабильный ID определяют порядок строк при равенстве.

Это общий рейтинг за всё время, не сезонный зачёт. Недельная активность, награды, смена группировки и совместные задания не входят в текущую реализацию.

## API

Все перечисленные маршруты требуют Bearer-токен.

| Маршрут | Запрос | Ответ |
| --- | --- | --- |
| `POST /me/character` | `{ name, avatar, factionId }` | `{ player: PlayerDto }`; создаёт персонажа один раз |
| `GET /leaderboard/factions` | — | `{ entries: [{ factionId, members, totalPoints }] }` |

`PlayerDto` содержит `factionId: FactionId | null`. Поля `race` в контракте больше нет. HTTP-ответы и событие Socket.IO `player` передают группировку через общий mapper.

Неизвестная группировка возвращает `400`. Попытка повторного создания персонажа, в том числе для выбора или смены группировки, возвращает `409`. Отсутствие авторизации — `401`.

## Обновление базы

- `0029_social_factions.sql` добавляет nullable-колонку `players.faction_id` и индекс. Старым персонажам группировка не назначается автоматически.
- Старая колонка `race` создавалась кодом запуска, а не прежними SQL-миграциями. Поэтому `0030_remove_races.sql` фиксирует переход схемы без безусловного `DROP COLUMN`, который сломал бы создание чистой базы.
- `initializeDatabase()` после миграций проверяет наличие `race` и удаляет колонку, если она существует. Повторный запуск безопасен; код больше не создаёт её заново.
- Dev-сброс персонажа очищает группировку вместе с состоянием создания; в обычном режиме этот маршрут недоступен.

Нужно обновить клиент и сервер вместе. При запуске нового сервера изменения базы применяются автоматически. Старый клиент отправляет другой контракт создания персонажа и несовместим с новым сервером.
